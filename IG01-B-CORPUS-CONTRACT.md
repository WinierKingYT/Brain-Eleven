# IG01-B Corpus & Ground Truth Contract

**Status:** CURRENT / BOUNDED CONTRACT  
**Package:** IG-01-B  
**Corpus version:** `ig-eval-v2`
**Scope:** corpus, labels, provenance, privacy and integrity only

IG01-B supplies measurement data for the already shipped IG01-A contract. It
does not run a provider, change ranking, change extraction rules, or modify
canonical memory authorities. IG01-C owns evaluator code after this package is
accepted.

## Dataset classes

| Class | Location | Status |
| --- | --- | --- |
| `PUBLIC_SYNTHETIC` | `evals/ig01b/public/ig-eval-v2/` | versioned and committed |
| `PRIVATE_REALISTIC` | ignored `evals/private/` | local-only mechanism; no committed cases |
| `SANITIZED_REAL_FAILURE` | `evals/ig01b/failures/` | empty reservation for IG-08 |

Public cases are generated by `ig01b-model-a-deterministic-template-v1`, which
is independent of the system under test. The generator is deterministic and
uses a fixed provenance date. Private and failure cases must contain hashes and
sanitized labels, never raw prompts, transcripts, memory content, credentials,
or tokens.

## Public corpus shape

`ig-eval-v2` contains 153 answerable cases: every one of the 17 phenomena and
each of `en`, `tr`, and `tr-en` occurs at least three times. The splits are
`dev`, `validation`, and `holdout`; the holdout has 39 cases and each holdout
case has two independent labels plus an adjudicated label. The recorded
inter-annotator disagreement is 0.0 for this synthetic seed. Six separate
`abstention` cases are unanswerable and are never included in normal precision
or recall denominators.

Phenomena are:

`explicit_decision`, `preference`, `lesson`, `requirement`, `suggestion`,
`hypothetical`, `question`, `negation`, `correction`, `quoted_material`,
`assistant_proposal`, `old_critical_decision`, `irrelevant_recent_memory`,
`wrong_project_candidate`, `superseded_memory`, `resolved_blocker`, and
`ambiguous_reference`.

Each record includes the IG01-A identity fields (`dataset_class`, version,
split, family/category, language, answerability, `data_lineage`, source IDs,
generator/SUT identity, contamination/privacy status), evidence references,
candidate/required/acceptable/forbidden/mandatory IDs, rationale, and ground
truth labels. Required and forbidden sets are disjoint by schema.

## Immutability and privacy gates

The current `ig-eval-v2/holdout.jsonl` is checked against all of:

1. the committed sidecar `holdout.sha256`,
2. the manifest hash, and
3. the pinned `PINNED_HOLDOUT_SHA256` constant in `evals/ig01b/integrity.py`,
4. the immutable `ig01b-corpus-v2` tag tree.

A holdout edit therefore fails CI; a deliberate change requires a new corpus
version and a new review/tag. Case IDs and normalized case fingerprints must be
unique across splits. The integrity checker also scans public bytes for common
credential/private-key patterns and common email/phone/IP PII forms.

`evals/private/` is ignored by Git and guarded by path checks. The private
writer validates the same case schema and recursively rejects raw-content
fields. The failure ingestion API validates the failure taxonomy, sanitized
flag, provenance and sanitization steps, rejects raw fields recursively, and
writes atomically under the IG-08 reservation. Its committed manifest has zero
cases by design.

## Answerability and labeling policy

An answerable case supplies enough scoped evidence for a competent system to
infer the expected result. Missing target/evidence cases are explicit
`case_kind=abstention` and `answerability.status=unanswerable`; they are scored
only for safe abstention by IG01-C. Holdout labels are independent before
adjudication, and disagreement is reported rather than hidden in an aggregate.

## Targeted prior art (adopt / reject)

The following design patterns were reviewed without importing their scores or
data into this corpus:

| Source | Adopt | Reject / guardrail |
| --- | --- | --- |
| [LongMemEval](https://arxiv.org/abs/2410.10813) | evidence locations, temporal fields, extraction/update/abstention families | its public release is not a DEV/VALIDATION/HOLDOUT protocol |
| [LoCoMo](https://arxiv.org/abs/2402.17753) | turn/session IDs, timestamps, evidence-level labels and adversarial/temporal strata | random conversation splits and external asset metadata can leak |
| [MemoryBench](https://arxiv.org/abs/2510.17281) | heterogeneous language/task strata and efficiency reporting | case-random split and one normalized aggregate |
| [Mem0](https://arxiv.org/abs/2504.19413) | explicit ADD/UPDATE/NOOP conflict labels and latency/token metrics | destructive delete semantics and dropped unanswerable cases |
| [Graphiti/Zep](https://arxiv.org/abs/2501.13956) | episode provenance and event/system time axes | automatic LLM contradiction supersession |
| [Letta archival memory](https://docs.letta.com/v1-sdk/memory/archival-memory) | current/archive tiers and on-demand retrieval | tags alone replacing evidence/lifecycle labels |
| [Supermemory API/repository](https://github.com/supermemoryai/supermemory) | source/provenance separation, memory-vs-RAG distinction and context-size measurement | hosted ranking and vendor benchmark claims are not copied into the benchmark |
| [ConvoMem paper](https://arxiv.org/abs/2511.10523) and [repository](https://github.com/SalesforceAIResearch/ConvoMem) | multi-message evidence distance, changing facts and explicit abstention strata | workload-specific full-context/RAG findings are not generalized without matched cases |
| [RAG evaluation survey](https://arxiv.org/abs/2405.07437) | candidate precision/recall, rank quality, answerability and efficiency/noise metrics | aggregate answer quality cannot mask candidate safety violations or mandatory-context misses |

These observations inform the data contract only. Any production change needs
its own later package and evaluation evidence.

## Acceptance evidence

Run:

```text
python -m pytest tests/test_ig01b_corpus.py -q
python -m evals.ig01b.generator --root evals/ig01b/public/ig-eval-v2
```

The first command is the CI gate. The second is a deterministic regeneration
check and must leave the pinned holdout hash unchanged. IG01-B cannot close
until an independent read-only reviewer returns `SHIP`; IG01-C remains closed
until then.
